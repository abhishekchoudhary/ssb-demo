Stupid. Simple. Blogging. Here.

Your words.
Your little corner.

A personal blog you own, published through GitHub. No terminal, installation, or code editing. You’ll use GitHub’s screens to create your blog and turn on publishing.

1. Choose your address

Create a GitHub account if you don’t have one.

A repository is the folder GitHub keeps for your blog. You get one personal site per account. If you already have one, choose a project site to keep it intact. A repository name cannot create a different github.io subdomain.

Search discovery

After choosing your address, check its host-root robots.txt and submit its sitemap in your verified search-console property. A project-level robots.txt does not control the host. Deployment does not prove indexing.

2. Create my blog

On GitHub, choose your account as owner, use the repository name above, choose Public, and click Create repository. Keep this guide open. GitHub checks the final name’s availability; do not delete or replace an existing site.

Continue to the verified template ↗

3. Confirm your repository

Create a fine-grained token for this repository. Contents: read/write. Pages: read.

4. Publish files or reconnect

Publish creates the static site from committed source. To resume a completed publication, enter a token and choose Check deployment; it does not save again.

5. Configure GitHub Pages

Then open Pages settings ↗. Choose Deploy from a branch → gh-pages → / (root) and save.

6. Verify your live site

Visit my blog ↗Open my editor ↗

7. Make it yours

Your editor lives at /admin/. Bookmark it. Connect with the same token to publish changes. The editor remembers your token in this browser and reconnects after reload. Use GitHub → Forget saved token to remove it.

Drafts remain in your source branch. A public repository exposes its source. Uploaded media is public by URL; unpublished PDFs are excluded.
